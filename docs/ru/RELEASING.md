# Релизы и автообновление

Это руководство для мейнтейнера. Оно объясняет, как публиковать релиз, чтобы у
пользователей была стабильная постоянная ссылка на скачивание, которая заодно
питает встроенную проверку обновлений.

## 1. Именование

Alter использует версии на основе даты: `ГГГГ.ММ.ДД` и название релиза, например `2026.11.02 Azoth`.

- **Тег:** `v2026.11.02`
- **Заголовок релиза:** `Alter 2026.11.02 Azoth`
- **Имя APK-ассета:** держите его **ровно** `app-release.apk` в каждом релизе, поскольку от этого
  имени зависит постоянная ссылка ниже, оно не должно меняться.

## 2. Публикация релиза

1. Перейдите в **Releases → Draft a new release**.
2. **Choose a tag** → введите новый тег (например, `v2026.11.02`) → *Create new tag
   on publish*.
3. Задайте **заголовок** и вставьте заметки (используйте `.github/RELEASE_TEMPLATE.md`).
4. **Прикрепите** сборку `app-release.apk` как бинарный ассет.
5. Оставьте включённой галочку **«Set as the latest release»**.
6. **Опубликуйте релиз.**

> Бинарники живут в Releases, а не в дереве репозитория. Не коммитьте APK в репо.

## 3. Постоянная ссылка на скачивание

Поскольку ассет всегда называется `app-release.apk`, а релиз помечен как последний, этот
URL всегда ведёт к свежему APK:

```
https://github.com/vanth34/Alter/releases/latest/download/app-release.apk
```

Используйте его для кнопки на сайте, в Telegram и для действия «Скачать обновление»
внутри приложения.

## 4. Проверка обновлений в приложении

Alter проверяет обновления, читая `update.json` из ветки `main` этого
репозитория:

```
https://raw.githubusercontent.com/vanth34/Alter/main/update.json
```

```json
{
  "versionCode": 2026110216,
  "versionName": "2026.11.02 Azoth",
  "apkUrl": "https://github.com/vanth34/Alter/releases/latest/download/app-release.apk",
  "sha256": "",
  "changelog": ["Каждая строка — отдельный пункт в окне обновления"]
}
```

- `versionCode`: если он больше установленного, Alter показывает окно обновления
  (Скачать, Позже, Пропустить).
- `versionName` и `changelog`: показываются в окне.
- `apkUrl`: откуда скачивается APK.
- `sha256`: контрольная сумма `app-release.apk` строчными буквами. Если заполнена, Alter
  проверяет загрузку перед установкой; если пустая, проверка пропускается.

Обновляйте `update.json` **последним**, после публикации релиза с `app-release.apk`,
иначе у пользователей будет битая ссылка на скачивание.

> Контрольную сумму можно получить командой `sha256sum app-release.apk` в Linux/macOS
> или `(Get-FileHash app-release.apk).Hash.ToLower()` в PowerShell.
